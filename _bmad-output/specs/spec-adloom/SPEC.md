# AdLoom — 제품 완성도 중심 BMAD 명세

`.memlog.md`의 사용자 방향과 결정에서 재도출했다. 고객 검증 불가·제품 완성도 우선은 확정된 기획 조건이다. 사용자 후속 지시로 공유 스키마·순수 검증을 구현했고 SC-015에 기록했다. root SPEC는 보존한다. 나머지 서비스·실연동·제품 완성은 아직 달성하지 않았다.

## Why

영상 1개와 설명으로 광고 소재를 생성하는 데서 끝내지 않고, 사람이 원본과 결과를 비교하고 잘못된 대상·문구·구간을 수정한 뒤 승인한 동일 내용을 PAUSED 광고로 준비하는 완결된 제품을 만든다. 고객 인터뷰·실사용 고객 확보·사업 성과는 이번 기획의 전제나 완료 기준이 아니다. 대신 심사자가 사용할 수 있는 전 과정, 원본에 연결된 검토·수정, 재현 가능한 미디어 품질과 실제 연동으로 완성도를 입증한다.

Meta 자체 도구가 이미 생성·훅·자막·엔드 장면 편집과 승인 흐름을 제공/시험 중이므로 단순 생성·승인만을 독창성으로 내세우지 않는다. 원본 근거와 변경 영향을 드러내는 제한 편집은 **차별성 가설**이며 시장 우위·독창성·우승을 확정하지 않는다. 공개 Indie 기준인 창의성·기술적 도전성·작동 여부는 모두 고려하되 공식 배점은 만들지 않는다.

## Capabilities

- **CAP-1**
  - **intent:** 사용자가 영상과 텍스트 또는 음성 설명으로 작업을 시작한다.
  - **success:** 3~45초 mp4/mov와 유효 설명을 받아 저장하고 잘못된 입력을 거부한다. 음성 설명은 전사된다. AC-01·02. 웹에서 시작하는 경로는 SC-011의 보완안이며 CLI도 유지한다.
- **CAP-2**
  - **intent:** 제품·주요 장면을 이해하고 광고 카피 후보와 검토할 위험을 제공한다.
  - **success:** 훅 3개와 유효한 구조화 결과를 반환한다. schema 재요청은 1회이고 반복 실패는 명시적 오류다. 차단 문구가 남으면 승인할 수 없다. AC-03·04·05. 문구의 출처·추론 구별은 CAP-9에 따른다.
- **CAP-3**
  - **intent:** 세 비율에서 제품을 따라가는 크롭과 추적 품질을 제공한다.
  - **success:** 비율·원본 경계·이동·보간을 검증하고 coverage<0.6이면 중앙 크롭과 degraded를 표시한다. AC-06·07·08·09. 포함 불가능 조건은 SC-002에 따라 명시하며, 기존 SAM 객체 후보의 사용자 선택은 CAP-9로 보완한다.
- **CAP-4**
  - **intent:** 배경·썸네일·엔드카드·자막으로 광고 소재를 보강한다.
  - **success:** Image 실패 시 대표 프레임·단색 엔드카드와 경고로 계속한다. 글자는 코드로 그리며 무오디오 영상은 자막을 만들지 않는다. AC-10. 생성 배경을 실제 촬영 근거로 표시하지 않는다.
- **CAP-5**
  - **intent:** 훅 A/B와 세 비율을 조합한 영상 6개를 검토하고 내려받는다.
  - **success:** 지정 해상도의 H.264/yuv420p/AAC 결과가 길이·오버레이·허용 출처 기준을 만족한다. 동일 snapshot과 고정 renderer 환경에서 decoded frame hash가 같다. AC-11·12·13·14. 새 revision 렌더 전에는 이전 결과를 최신 결과로 표시하지 않는다.
- **CAP-6**
  - **intent:** 사람이 현재 결과와 위험을 검토한 뒤 특정 내용의 게시를 승인한다.
  - **success:** 6개 미리보기·정책·degraded를 확인하고 미승인 게시를 차단한다. 수정하면 승인이 무효화된다. AC-15. SC-003의 content fingerprint와 SC-011의 웹 흐름으로 승인 대상과 실제 게시 내용의 일치를 확인한다.
- **CAP-7**
  - **intent:** 승인된 9:16 훅 A/B를 실제 테스트 광고 계정의 PAUSED 광고 2개로 준비한다.
  - **success:** campaign/adset/ad는 PAUSED이고 확정된 생성 ID를 재사용한다. AC-16·17. 실제 read-back·소재 대응이 필요하며 fixture/replay 결과로 live 완료를 대체하지 않는다. status 정정·결과 불명 처리는 SC-001·004를 따른다.
- **CAP-8**
  - **intent:** 사용자가 작업 진행을 이해하고 실패 후 기존 작업을 복구한다.
  - **success:** CLI와 웹이 같은 job·산출물·오류를 사용한다. 모델·비밀·LIVE 게이트를 강제하고 실패 단계를 재개한다. AC-18·19·20·21 및 원본 전이표. 키가 없으면 설정 필요 상태를 표시하며 mock으로 조용히 바꾸지 않는다.
- **CAP-9**
  - **intent:** 장면·문구의 원본 근거를 확인하고 잘못된 대상·구간·텍스트를 제한된 조작으로 수정한다.
  - **success:** 장면 선택은 source timestamp, 문구는 정확한 입력 span 또는 관찰 구간으로 이동한다. 명시 입력·영상 관찰·모델 추론을 구별한다. SAM 기존 object 후보 선택, 구간 선택, 훅·카피·자막 수정 후 영향받는 결과를 재생성하고 기존 승인을 차단한다. 근거 연결을 진실·효능·정책 승인 보증으로 표시하지 않는다. SC-012, PQ 기준으로 검증한다.

## Constraints

- **고객 인터뷰·실고객 모집·매출/CTR/구매전환 실험은 요구하지 않는다.** 직접 촬영하거나 적법한 사용 권리를 확보한 실물 영상과 합성 fixture로 품질을 검증한다.
- 원본 INV-1~8의 안전 의도를 유지한다. 영상 생성·자동 광고 활성화·승인 없는 게시를 허용하지 않는다. layer/asset 경계 명료화는 SC-007의 제안이다.
- 최종 범위는 3비율×2훅 영상 6개와 실제 PAUSED 광고 2개다. 품질 우선을 이유로 실제 연동을 가짜 결과나 다운로드만으로 축소하지 않는다.
- FastAPI와 단일 HTML, Python 라이브러리/CLI, 파일 job 구조를 유지한다. 웹을 전 과정으로 확대하는 SC-011은 제안이며 DB·분산 작업 큐·새 frontend framework를 추가하지 않는다.
- fixture·저장된 실결과 replay·새로운 live 실행은 구분한다. H2/H3와 LIVE 승인 없이는 유료 모델 호출이나 광고 생성으로 넘어가지 않는다.
- SC-013은 H1의 사전 개발 허용 여부도 실행 선행으로 제안한다. 공식 허용 시점 확인 전에는 기획·권리 확인·데이터 설계만 준비하며 일정 압박으로 개발 시작 규정을 추정하지 않는다.
- 모델 문구·timestamp는 신뢰된 사실이 아니다. 출처 범위·revision·정책 검사를 거치며 가격·할인·효능·성능 주장의 명시 근거가 없으면 검토를 차단한다. 사용자 입력도 사실 검증 완료로 표현하지 않는다.
- SC-001~SC-015는 root SPEC에 미반영이다. 사용자 지시로 schema 범위를 구현했으나 config와 나머지 모듈은 미구현이므로 T00/T01을 부분 진행으로 기록한다. 스키마 검증을 전체 INV·live gate 완료로 확대하지 않는다.

## Non-goals

- 광고 자동 활성화·결제·다중 계정/팀·성과 분석·영상 생성·모바일 앱·공개 SaaS.
- 범용 비디오 편집기, 자유 mask 그리기, 무제한 대화형 재생성, 자동 광고비 최적화, 4:5·1:1 실제 게시.
- 고객/시장 검증 수행, 광고 효과 개선 주장, 임의 심사 점수·우승 확률.
- 현재 스키마 구현 범위를 넘어서는 제품 서비스·live 호출·제출·push.

## Success signal

심사자가 웹에서 권리 확보 실물 영상을 입력하고, 원본 근거를 확인해 대상·문구 중 하나를 수정한 후, 최신 revision의 영상 6개를 재생·다운로드하고 승인한다. 이어 실제 테스트 계정의 PAUSED 광고 2개와 승인 내용이 일치함을 확인한다. 실패·부분 게시·stale approval도 명시적으로 처리해야 한다.

품질 증거는 사전 고정한 12개 미디어 사례(합성 8·실물 4), 분리한 개발/평가 집합, 기존 AC21·BA18 및 PQ01~PQ10으로 만든다. 고객 영상이 필수였던 원본 T15는 자체 권리 확보 실물로 대체하는 SC-013을 제안한다. 위 항목은 목표이며 현재 제품 구현·검증 결과가 아니다.

## Assumptions

- `[가정]` 로컬 단일 운영자·desktop browser를 기준으로 하고, 직접 촬영 생활용품 단일 제품을 대표 데모로 권장한다. 실제 데이터는 아직 확보했다고 주장하지 않는다.
- `[가정]` 웹사이트 방문 목적을 기본안으로 검토하되 실제 destination·계정·Page·예산·objective/optimization 조합은 H3에서 확정한다.
- `[제안]` 구현 초기에 웹 vertical slice와 provider 연동 검증을 배치하고 마지막 2일은 품질/리허설에 사용한다. 특정 배포 프레임워크나 운영 기능을 추가하는 계획이 아니다.

## Open Questions

1. SC-001~SC-015의 루트 명세 반영과 H1 공식 규정·사전 제작물 허용 여부. 스키마 착수 지시를 전체 제품 기능·실호출의 승인으로 해석하지 않는다.
2. H2/H3의 실제 API 접근, 비용 한도, 계정·권한·destination·예산, 촬영/사용 권리와 파일 보관 정책. 고객 모집은 이 질문에 포함하지 않는다.
3. H4 제출 형식·심사 접근 방식: 로컬 실행·녹화·실행 패키지 중 공식 요구를 확인한다. 심사자가 원격 서버를 요구하면 현재 local-only 범위와 별도로 조정해야 한다.
